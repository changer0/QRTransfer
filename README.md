# QRTransfer

个人离线光学传输工具。Windows 双击 sender.html 发送；手机打开 Pages 接收页面，首次加载后可离线使用。文件不上传到任何服务。仅在获准传输的数据与设备上使用。

## 构建

`npm ci && npm test && npm run build`

dist/sender.html 为独立离线文件；dist/index.html 为 HTTPS/PWA 接收入口。Pages 使用 GitHub Actions，需在仓库设置中启用。私有仓库需要支持 Pages 的 GitHub 套餐；发布页面可能公开，不包含实际传输文件。

## 传输协议

### 快捷操作与自动恢复

发送端选择文本或文件后点击「开始传输」。传输设置默认折叠，档位和压缩偏好会尽量记忆。发送过程中可实时调整 1–24 fps（不改变原始分片结构），一键全屏、暂停、继续或补帧；首轮进度达到 100% 表示完成一轮播放，并非接收成功。常亮在浏览器支持且系统允许时自动申请，暂停、完成或离开页面后释放。

接收端自动读取本地 IndexedDB 中的最近一次 QRT2 接收任务，恢复已完成分块及未完成帧，继续扫描即可；已授权且浏览器允许时自动启动摄像头。首轮结束标记到达或有效进度停滞 8 秒时提示快速补帧，点击后暂停扫描并显示补帧请求，发送端进入补帧后点击「继续扫描」。详细帧网格按需展开。

接收数据保存在设备本地，已完成结果也会保留至主动重置或接收新文件；请在保存后按需清除。存储失败时提示不要关闭页面；浏览器清理站点数据、存储配额、无痕模式或系统回收可能影响恢复。支持 Web Locks 时阻止同源多接收页并行写入；否则使用会话绑定防止混入不同文件，建议始终只打开一个接收页。发送端不持久化原始文件，若关闭发送页面，重新选择相同文件及相同编码参数即可继续接收端已有任务。旧 QRT1 仅支持当前页面内的接收进度。

复核：\`npm test\` 执行协议测试；构建后运行 \`node scripts/review-p0.cjs\` 执行浏览器验收（需要 Playwright 和 Chromium；也可通过环境变量 PLAYWRIGHT_MODULE、CHROME_PATH 指定已有安装）。覆盖模拟摄像头、断网刷新、补帧、缓存清除、常亮生命周期模拟、全屏和响应式布局。真实设备权限及物理屏幕/相机性能需实机验证。

### 缺帧检查与定向补传

接收端按数据块展示完成、未完整、未识别状态。选择未完整的数据块可查看原始帧编号，其中直接接收、喷泉码冗余恢复、待接收分别用绿色、蓝色、红色表示。尚未收到整块时无法知道精确压缩后帧数，标为未识别并补发整块。

首轮循环结束或接收停滞后，点击「生成补帧码」（最多 12 个未完成块，优先部分接收的块），也可选择「仅补当前块」。发送端保持原始任务，扫码读取手机上的补帧二维码，或输入 QRF1 文本码，开始定向补帧。发送端仅循环播放请求中列出的原始帧，补帧帧率不高于 6 fps；手机继续接收即可，已有进度不会被清空。若仍有缺帧，重新生成补帧码。发送端需要摄像头权限才能扫码，离线 HTML 的摄像头兼容性依浏览器而定；手动输入不需要摄像头或网络。

补帧请求按会话标识、分块编号和帧编号范围绑定当前编码任务；不改变原始编码密度与压缩参数。最终仍必须通过原始文件的 SHA-256 校验。旧版 QRT1 接收兼容不提供此功能。

QRT2 + 96-bit 会话标识 + 分块编号 + BC-UR bytes。发送端分块计算文件 SHA-256，通过 Blob.slice 按需读取 32 KiB 数据块；每块独立使用喷泉码，循环发送系统帧及冗余帧。文件元信息随每块重复发送，接收端支持乱序、重复、漏帧及跨轮补偿；最后按块顺序校验整文件长度与 SHA-256，校验失败不提供保存。QRT2 接收端兼容旧 QRT1 发送端；旧接收端需升级才能接收 QRT2。SHA-256 不提供保密性或发送者身份认证。

二维码编码：qrcode (MIT)，解码：jsQR (Apache-2.0)，喷泉码：@ngraveio/bc-ur (MIT)，SHA-256：sha.js (MIT)。所有依赖在构建时本地打包，不使用运行时 CDN。依赖许可证详见 npm 包内 LICENSE。

QRT2 不设固定文件大小上限，但接收端在浏览器内存保留数据块，最终生成 Blob，实际容量及耗时受设备、浏览器及光学通道约束。发送端支持超稳（2 fps / 350 B）、兼容（6 fps / 450 B）、均衡（12 fps / 850 B，默认）、高速（18 fps / 1200 B）、极速（24 fps / 1450 B）五档目标帧率与单帧载荷。可选逐块 DEFLATE 无损压缩，仅当压缩后更小时使用；新版接收端兼容旧协议，旧接收端须升级才能接收高密度或压缩数据。接收端优先使用浏览器原生二维码识别（支持时），否则使用 Web Worker 解码，并根据摄像头帧更新调度。接收速度基于最近 5 秒恢复的有效原始数据估算，重复帧不增加有效字节。超过 1 MiB 的文本仅提供文件保存，避免大文本渲染影响界面。QRT2 已支持本地断点续传（仍在内存维护当前解码数据，超大文件的低内存流式导出尚未实现）；没有加密和自动确认通道。性能及 iOS/Android 实机兼容性需要验证。PWA 在线优先获取最新页面，断网回退本地缓存，资源带版本标识；PWA 缓存可能被操作系统清理。
